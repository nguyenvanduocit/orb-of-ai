## Goal and meaning of 100%

DiscordHero reproduces every recoverable TaskbarHero datum, rule, progression
path, and player decision while presenting the game through Discord Components
V2. "100%" is an acceptance claim, not a similarity claim:

1. Every authoritative catalog row is represented without renaming,
   procedural substitution, or lossy field selection.
2. Every recovered formula and state transition has executable conformance
   fixtures.
3. Every player-visible system is reachable from one private `/discordhero`
   workspace.
4. Anything the snapshot cannot prove is an explicit runtime-oracle item. It
   cannot be filled in by intuition and cannot count as complete.
5. Discord-specific presentation may paginate or regroup information, but it
   may not change game semantics, probabilities, costs, caps, unlocks, or
   rewards.

Literal desktop layout, animation, audio playback, Steam inventory settlement,
and live Steam Community state cannot be demonstrated from a Markdown export.
Their underlying catalog metadata and recovered rules remain required; exact
runtime behavior remains open until the oracle gates below pass.

## Replacement boundary

The disconnected synthetic hero/world/gear/formation scaffold and its
assumption tests were removed after a dependency audit. The pinned catalog is
the only TaskbarHero data source for DiscordHero.

The active `/rpg` model remains a confirmed replacement target:

- It has three classes, a level-50 cap and unrelated
  prestige/atlas mechanics ([`src/rpg.ts:23`](../src/rpg.ts#L23),
  [`src/rpg.ts:117`](../src/rpg.ts#L117), [`src/rpg.ts:204`](../src/rpg.ts#L204)).
- Its armor/resistance implementation hard-codes different caps and constants
  ([`src/rpg-combat.ts:105`](../src/rpg-combat.ts#L105)).

Tests that merely preserve those generated assumptions do not demonstrate
DiscordHero parity. Their replacement criteria are the source-count,
cross-reference, golden-formula, deterministic-trace, transaction, restart,
stale-revision, duplicate-interaction, and end-to-end workspace gates in this
document.

## Definition of done

The 100% claim is allowed only when all of the following are true:

- The generator verifies the manifest digest and imports all 45 datasets /
  25,757 rows with zero schema loss, unresolved required relation, or invented
  replacement record.
- Every matrix row above has an automated acceptance test and all required
  runtime-oracle rows are promoted from **LOW** with attached evidence.
- Two independent implementations of critical arithmetic (production engine
  and fixture oracle) agree across golden vectors and property tests.
- A seeded full journey—fresh state, hero setup, stage combat, death/recovery,
  offline resume, equip, rune, crafting, cube, synthesis, storage and
  collection—replays to the same state digest across process restarts.
- Concurrent commands for different players proceed independently; concurrent,
  duplicate, and stale commands for one player preserve conservation and apply
  at most once.
- Every Discord view is Components V2 for its full message lifecycle, remains
  private by default, paginates within Discord limits, and has no dead-end
  action.
- Game gold never changes Orb coins, and Orb coin activity never changes
  DiscordHero gold.
- Old RPG JSON is unchanged byte-for-byte throughout migration, testing, and
  deployment.
- Command registration, startup, guild cleanup, server/wiki, agent tools,
  container build, typecheck, unit/property/integration tests, and a real
  Discord smoke test all pass against the same catalog digest and schema
  version.
- A separate verifier reviews evidence after implementation; green typecheck or
  unit tests alone do not authorize the parity claim.
